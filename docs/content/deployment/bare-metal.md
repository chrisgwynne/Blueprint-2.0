# Bare Metal (Linux Server)

This guide covers deploying Blueprint directly on a Linux VPS or dedicated server without Docker. You manage the process yourself using systemd — the same init system that runs every other service on Linux.

**Tested on:** Ubuntu 22.04, Ubuntu 24.04, Debian 12.

> [!NOTE]
> If Docker is available on your server, the [Docker deployment](/deployment/docker) guide is simpler and produces an equivalent result. Use the bare-metal path when Docker is not available, when you prefer direct process management, or when you need predictable resource allocation on a small VPS.

---

## Prerequisites

- A Linux server running Ubuntu 22.04/24.04 or Debian 12
- A non-root user with `sudo` privileges
- Git installed (`sudo apt install git`)
- At least 1 GB RAM (2 GB recommended)
- At least 5 GB free disk space
- A domain name pointed at your server's IP (for HTTPS)

---

## Step 1 — Install Bun

Blueprint's server runtime is Bun. Install it as a non-root user:

```bash
curl -fsSL https://bun.sh/install | bash
source ~/.bashrc
bun --version
```

---

## Step 2 — Clone to /opt/blueprint

```bash
sudo mkdir -p /opt/blueprint
sudo chown $USER:$USER /opt/blueprint
git clone https://github.com/your-org/blueprint.git /opt/blueprint
```

---

## Step 3 — Run Setup

```bash
cd /opt/blueprint
bun run setup
```

`bun run setup` installs all dependencies for both server and client workspaces, generates random secrets, and initialises the SQLite database.

---

## Step 4 — Configure .env

```bash
cp /opt/blueprint/.env.example /opt/blueprint/.env
nano /opt/blueprint/.env
```

Required values to set:

```bash
# Generated by setup — verify these are set
ENCRYPTION_KEY=<64-char hex string>
SESSION_SECRET=<64-char hex string>

# Change from the default immediately
ADMIN_PASSWORD=your-strong-password

# At least one LLM provider
OLLAMA_BASE_URL=http://localhost:11434
# or: ANTHROPIC_API_KEY, OPENAI_API_KEY, GOOGLE_GEMINI_API_KEY

# Your production URL (used for OAuth callbacks)
CLIENT_URL=https://blueprint.yourdomain.com
```

> [!WARNING]
> Do not leave `ADMIN_PASSWORD=changeme`. It is the public default and will be the first thing attempted by anyone who finds your server. Set a strong password before exposing Blueprint to the internet.

---

## Step 5 — Build the Frontend

```bash
cd /opt/blueprint
bun run build
```

This compiles the React client and writes built files to `client/dist/`. The server serves these as static assets. Without this step, Blueprint will show a white screen.

---

## Step 6 — Create a Dedicated System User

Run Blueprint as a dedicated user rather than as root or your personal account:

```bash
sudo useradd --system --shell /bin/false --home /opt/blueprint blueprint
sudo chown -R blueprint:blueprint /opt/blueprint

# Install Bun for the blueprint user so the service can find it
sudo -u blueprint bash -c 'curl -fsSL https://bun.sh/install | bash'
```

---

## Step 7 — Create the systemd Service

```bash
sudo nano /etc/systemd/system/blueprint.service
```

Paste the following:

```ini
[Unit]
Description=Blueprint Business OS
Documentation=https://docs.blueprint.sh
After=network.target
Wants=network.target

[Service]
Type=simple
User=blueprint
WorkingDirectory=/opt/blueprint
ExecStart=/home/blueprint/.bun/bin/bun run start
Environment=NODE_ENV=production
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal
SyslogIdentifier=blueprint
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

The key fields:

| Field | Value | Purpose |
|-------|-------|---------|
| `User` | `blueprint` | Runs as dedicated user — not root |
| `WorkingDirectory` | `/opt/blueprint` | Blueprint reads `.env` from here |
| `ExecStart` | `.../bun run start` | Starts the production server |
| `Restart=always` | — | Restarts on crash or clean exit |
| `RestartSec=10` | — | Waits 10 s before each restart attempt |

> [!NOTE]
> The `ExecStart` path `/home/blueprint/.bun/bin/bun` points to Bun installed for the `blueprint` user. If Bun is installed at a different path (check with `sudo -u blueprint which bun`), update this line accordingly.

---

## Step 8 — Enable and Start

```bash
sudo systemctl daemon-reload
sudo systemctl enable blueprint
sudo systemctl start blueprint
```

Verify it is running:

```bash
sudo systemctl status blueprint
```

View live logs:

```bash
sudo journalctl -u blueprint -f
```

Blueprint is now accessible at `http://your-server-ip:4000`.

## Nginx Reverse Proxy with SSL

Expose Blueprint on port 443 with a valid certificate. Blueprint uses Server-Sent Events (SSE) — the proxy must support long-lived connections.

### Install Nginx and Certbot

```bash
sudo apt install nginx certbot python3-certbot-nginx
```

### Create the site config

```bash
sudo nano /etc/nginx/sites-available/blueprint
```

```nginx
server {
    listen 80;
    server_name blueprint.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name blueprint.yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/blueprint.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/blueprint.yourdomain.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    location / {
        proxy_pass         http://localhost:4000;
        proxy_http_version 1.1;

        # Standard proxy headers
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;

        # WebSocket and SSE support
        proxy_set_header   Upgrade           $http_upgrade;
        proxy_set_header   Connection        "upgrade";

        # SSE: disable buffering, extend timeout
        proxy_buffering    off;
        proxy_cache        off;
        proxy_read_timeout 86400s;
    }
}
```

Enable the site and get a certificate:

```bash
sudo ln -s /etc/nginx/sites-available/blueprint /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d blueprint.yourdomain.com
```

> [!WARNING]
> `proxy_buffering off` and `proxy_read_timeout 86400s` are both required for SSE. Without `proxy_buffering off`, real-time task updates are buffered and never reach the browser. Without the long timeout, SSE connections drop after 60 seconds and the UI repeatedly reconnects.

---

## Firewall

Only expose ports 80 and 443. Blueprint's port 4000 should not be directly reachable from the internet:

```bash
sudo ufw allow ssh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

---

## Updates

```bash
cd /opt/blueprint
git pull
bun install
bun run build
sudo systemctl restart blueprint
```

Blueprint runs database migrations automatically on startup — no manual migration step is needed. After restarting, check the service is healthy:

```bash
sudo systemctl status blueprint
curl http://localhost:4000/api/health
```

---

## Backup

Blueprint's entire state lives in `/opt/blueprint/data/`. Back it up regularly:

```bash
tar -czf blueprint-backup-$(date +%Y%m%d).tar.gz /opt/blueprint/data
```

`data/` contains the SQLite database, connector sync state, task history, and all signal history. If you have customised agent soul files, also include `/opt/blueprint/server/agents/` in your backup.

> [!TIP]
> For an automated daily backup, add this to the `blueprint` user's crontab or create a systemd timer. Sync the resulting `.tar.gz` to an offsite location — S3, Backblaze, or an external drive.
